# Private socket memory audit

This directory contains a read-only source verifier and an actual Vulkan ICD
byte probe. It does not patch or enable any profile. Public/default v2/v3 code
is unchanged. An additional guest projection is absent because the audited
host decoder already projects noncoherent guest memory under the socket feature
constraints below. Runtime confirmation is still outstanding.

## Contract and source evidence

Mesa is pinned to `541c56aa3fd24027ed46ae350287d21dcd56c901`; the host gfxstream
revision is `f0ce013371a68e85b5a1a1b0cf14ac9ad729f4be`. `verify_sources.py`
contains SHA-256 hashes of the exact prepared guest source read during this
audit. It verifies file contents, not the decoder binary or runtime feature set.

The provider's memory-type indices are not an application allocation contract.
The decoder's `vk_emulated_physical_device_memory.cpp` creates guest types,
retains each guest type's `hostMemoryTypeIndex`, and translates memory requirement
masks through that mapping. `getHostMemoryInfoFromGuestMemoryTypeIndex` resolves
an ordinary guest allocation to the backing type. External imports have another
path and are outside this probe.

With `GlDirectMem` and `VirtioGpuNext` false, the decoder clears HOST_COHERENT.
`VulkanDisableCoherentMemoryAndEmulate` can re-add it; that option is incompatible
with the socket shadow's explicit visibility contract. `SystemBlob` on Apple
and `VulkanUseDedicatedAhbMemoryType` can insert types and change indices. Record
all these actual immutable feature values from the decoder used for a run;
defaults or a source revision alone do not prove them. `ExternalBlob` must also
be false for the audited explicit-byte path.

The reported macOS provider types `[0x1, 0xf, 0x11]` therefore imply guest types
`[0x1, 0xb, 0x11]` only under the stated feature constraints. This is a source
inference, not captured guest output or phone evidence. Backing type 1 being
coherent is compatible with guest type 1 requiring explicit flush/invalidate.
No guest allocation index is silently substituted by this directory.

In the exact prepared guest:

- `autogenerated/func_table.cpp` sends legacy, core 2 and KHR 2 memory queries
  directly through their corresponding encoder methods. None uses the
  ResourceTracker memory-property query hook. A hook-only projection misses
  these application entrypoints.
- ResourceTracker's internal `getPhysicalDeviceMemoryProperties` caches the
  decoder reply. Device creation separately stores another decoder reply.
  Neither is a raw physical-provider query. Generated memory-type transforms
  do not remap indices. Ordinary Linux buffer/image requirements preserve the
  decoder's mask; external-resource paths are distinct.
- The socket shadow allocation passes the requested guest index unchanged to
  the encoder. It rejects coherent guest types, pNext and custom allocators.
  An allocation retains its full-size local shadow. Mapping returns base plus
  offset; encoder transfers use that base plus absolute allocation offset.
- The shadow validator checks atom alignment, mapping bounds and the allocation
  end exception. The encoder canonicalizes WHOLE_SIZE to the guest mapping end.
  Flush sends a uint64 byte count and actual bytes after the declared packet.
  Invalidate reads the provider result and each exact count/payload into staged
  storage; only complete success publishes staged bytes. A count mismatch or
  truncated response loses the stream. Fence completion does not fetch bytes.

Vulkan requires at least one HOST_VISIBLE | HOST_COHERENT memory type
([Khronos memory properties](https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceMemoryProperties.html)).
A private profile with none cannot be a conformant general Vulkan implementation.
Physical coherence does not supply remote coherence. This diagnostic makes no
conformance, unmodified-game, phone, presentation or general-driver claim.

## Checks and isolated execution

Source-only checks, requiring Python 3 and no compiler:

```sh
python3 -m unittest discover -s guest/gpu/gfxstream/private-memory-profile -p 'test_*.py'
python3 -m unittest discover -s guest/gpu/gfxstream -p test_shadow_protocol.py
python3 guest/gpu/gfxstream/private-memory-profile/verify_sources.py /isolated/prepared-mesa
```

The probe uses ordinary Vulkan loader calls through the actual private ICD,
not an encoder substitute, fake decoder, or helper model. It needs a Linux C++17
compiler, Vulkan headers and loader already present in the worker image. After
parent scheduling, compile in a NEW writable scratch directory on actual
`/data`, outside the full `/data/bb` symlink. Use the existing worker image digest
`sha256:b94dd0452b1d2164d52115722c333cbb51f903e736fa7e7e782d21c52cf40442`,
with one CPU, bounded memory and no package installs. Mount retained artifacts
read-only and own only the new diagnostic process/receiver. No Mac compilation
or execution is part of this slice.

Inside that isolated job, with the source and artifacts explicitly mounted:

```sh
c++ -std=c++17 -O1 -Wall -Wextra memory_probe.cpp -lvulkan -o memory_probe
VK_DRIVER_FILES=/isolated/private-icd.json CABOOSE_GFXSTREAM_SOCKET=/isolated/decoder.sock timeout 30s ./memory_probe 1985229328
```

Use the retained v2 diagnostic first to measure existing semantics. Repeat on
v4 only with the parent's matching v4 guest/decoder artifacts and exact handshake;
this probe neither selects nor relaxes their protocol. Never point it at an
owner listener, phone, or system ICD. The probe requires Vulkan 1.1 and the
advertised KHR properties2 extension so that no skipped query alias can count as
success. It selects a guest-advertised HOST_VISIBLE noncoherent type compatible
with all three buffers; inability to select one is failure, not a fallback.

The probe compares legacy/core/KHR memory types and heaps, legacy/core buffer
requirements, then prints the selected index, mask, allocation size and offsets.
Two source buffers alias one allocation at a nonzero binding offset. It publishes
a challenge through a partial nonzero-offset mapping, poisons only the local
shadow after flush, copies through the alias on the actual GPU, waits a bounded
fence, and invalidates the destination. Every byte and guard is compared. It also
checks WHOLE_SIZE at a partial mapping end, zero offset, and a four-byte range at
the unaligned allocation end. Its uninvalidated-shadow assertions deliberately
test this private shadow implementation, not portable Vulkan visibility timing.
A tail failure is significant: the decoder rounds backing allocation sizes, so
a guest allocation-end exception needs correct handling against the actual
backing size; no acceptance is inferred from the guest validator alone.

For loss, run `memory_probe CHALLENGE loss-before-invalidate` under the same
30-second outer timeout. After its flushed `READY` line, the harness revokes
only its own transport, then sends one input byte. The probe requires
VK_ERROR_DEVICE_LOST and an entirely unchanged destination shadow. Its process
exit does not prove native retirement; the harness must obtain cleanup/retirement
or quarantine the isolated receiver. This mode intentionally performs no further
Vulkan calls over the lost stream.

Acceptance additionally requires decoder-side immutable feature and backing-index
receipts, two challenges with byte-identical expected results, and fault-injected
actual decoder replies: provider failure, truncated length, wrong length,
truncated first/later payload and multiple overlapping ranges. Preserve sent
ranges, returned counts, exact bytes and unchanged-shadow evidence. The existing
Python fixtures check rejection logic only; they cannot close these transport
gates. The current probe does not implement provider-failure or mid-response fault
injection, invalid API-range tests, image requirement checks or multiple-range
invalidate. Neither this document nor a successful simple run claims those pass.
