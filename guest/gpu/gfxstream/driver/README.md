# Caboose guest Vulkan driver

`libvulkan_gfxstream.so` is the Vulkan driver applications on a Caboose computer load.
It is Mesa's gfxstream guest encoder, built from a pinned Mesa revision with the patch
series in this directory and the Caboose-owned sources beside it. It sends Vulkan calls
over a Unix socket to the GPU broker (`../caboose-gpu-broker`), which relays them to the
phone's decoder; the protocol is in [docs/gpu-live.md](../../../../docs/gpu-live.md).

## Building

```sh
guest/gpu/gfxstream/driver/build.sh OUTPUT_DIRECTORY
```

needs Docker and git on an x86-64 Linux host. The first build fetches Mesa
`541c56aa3fd24027ed46ae350287d21dcd56c901` into `$CABOOSE_MESA_CACHE` (default
`~/.cache/caboose/mesa-<revision>`) with `../fetch_mesa.sh`; the build itself runs in a
container without network. `CABOOSE_BUILD_JOBS` sets its parallelism and CPU limit
(default 4) and `CABOOSE_BUILD_NICE` its scheduling priority (default 0).

`OUTPUT_DIRECTORY` must be empty or absent. It receives:

| File | What |
| --- | --- |
| `libvulkan_gfxstream.so` | The driver |
| `i386/libvulkan_gfxstream.so` | The driver for 32-bit applications, cross-compiled for i386 |
| `caboose-driver.json` | The Mesa revision and the SHA-256 of every patch and owned source the build used |
| `SHA256SUMS` | The other files' hashes |

The build environment is [`Dockerfile`](Dockerfile): a digest-pinned Debian 13 image
whose packages come from a fixed `snapshot.debian.org` date, so the compiler, headers and
libraries do not change between builds. `compile.sh` runs in it with fixed paths
(`/work/mesa`, `/work/build`), so the same repository commit produces a byte-identical
library on any host.

Its soname is `libvulkan_caboose_gfxstream.so`, not Mesa's: Mesa's packaged gfxstream
manifest, on the computer and in Flatpak runtimes, names its library by the bare
`libvulkan_gfxstream.so`, which the dynamic loader would resolve to this driver once loaded,
and the Vulkan loader would list the phone's GPU twice.

The library is linked against Debian 13's glibc, libstdc++ and `libwayland-client.so.0`,
which the computer image provides. Applications select it through a Vulkan loader
manifest (`../make_manifest.py`) and run with `CABOOSE_GFXSTREAM_SOCKET` set to the
broker's socket.

## Layout

`prepare.py MESA_CHECKOUT` turns a clean checkout of the pinned revision into the driver
source tree: it applies `patches/` in order with `git apply` (no fuzz) and copies the
Caboose-owned sources to the paths the patches include them from:

| Repository source | Mesa path |
| --- | --- |
| `../SocketStream.{h,cpp}` | `src/gfxstream/guest/connection-manager/` |
| `../virtual-wsi/{client.h,client.cpp,wire.h,mesa_surface.inc,mesa_swapchain.inc}` | `src/gfxstream/guest/vulkan/caboose-wsi/` |
| `../bounded-memory/*.h` | `src/gfxstream/guest/vulkan_enc/caboose-bounded-memory/` |
| `../dmabuf/*.h` | `src/gfxstream/guest/vulkan_enc/caboose-dmabuf/` |
| `../media/{gpu_media.h,media_import.h,media_import.inc}` | `src/gfxstream/guest/vulkan_enc/caboose-media/` |
| `../feature-emulation/{feature_emulation.h,d3d11_emulation.h,d3d11_tracker.inc}` | `src/gfxstream/guest/vulkan_enc/caboose-features/` |
| `../shader-cache/shader_cache.h` | `src/gfxstream/guest/vulkan_enc/caboose-shader-cache/` |

Patches change upstream files only; a patch that touches an owned path is rejected. The
owned sources are ordinary files with their own unit tests
(`../bounded-memory/README.md`, `../virtual-wsi/README.md`, `../feature-emulation/README.md`).

the prepared state, edit, and regenerate the affected patch with `git format-patch`
against the commit before it; then rebuild and run the tests below.

## Capability negotiation

Before Mesa's first command, `SocketStream.cpp` sends a 48-byte hello: `CBGLREF1`, a
little-endian version (4) and feature mask, and the source fingerprint documented in
[docs/gpu-live.md](../../../../docs/gpu-live.md). The driver offers mask `0xFBFFF0`; the
broker answers with the required `0x70` plus the offered bits the connected phone
supports, and the driver prints `CABOOSE_GPU_HELLO features=0x…` with what it was granted. A
broker that predates a bit closes the connection, and the driver reconnects offering fewer:
`0x3BFFF0`, `0x1BFFF0`, `0xBFFF0`, `0x3FFF0`, `0x1FFF0`, `0xFFF0`, `0x7FF0`, `0x3FF0`, `0x1FF0`, `0xFF0`, `0x7F0`, `0xF0`, then `0x70`. An answer with bits the driver did not offer, or
any other difference, fails the connection, and with it Vulkan instance creation.
`CABOOSE_GFXSTREAM_GUEST_HANDLES=0` offers `0x70` only. Patches 0013 and 0014, the
creates and allocations of 0016 and the fence, semaphore and pipeline handles of 0018
take effect only with bit 7; descriptor set and command buffer handles need bit 8,
patch 0021 bit 9 and patch 0022 bit 10. When bit 9 is agreed, the driver opens a second stream with the same
hello for the completion feed. The rest of the series requires the `0x70` contract.

| Bit | Meaning |
| --- | --- |
| 4 (`0x10`) | Upstream null-optional-strings wire format |
| 5 (`0x20`) | Live presentation through the virtual WSI |
| 6 (`0x40`) | Indexed swapchain acquisition |
| 7 (`0x80`) | The device registers objects under guest-assigned handles |
| 8 (`0x100`) | Also descriptor sets and command buffers (requires bit 7) |
| 9 (`0x200`) | The device serves the completion feed |
| 10 (`0x400`) | Presents are ordered behind device-stream marks (`SWAPCHAIN_PRESENT_ORDERED`) |
| 11 (`0x800`) | Swapchain images are the guest's own |
| 12 (`0x1000`) | Query pools use guest-assigned handles (requires bit 7) |
| 13 (`0x2000`) | Shader modules the phone keeps are named by hash (patch 0041) |
| 14 (`0x4000`) | The executor resumes across a lost socket and suspends in the background: surface waits have no 10 s deadline (`../virtual-wsi/mesa_surface.inc`) |
| 15 (`0x8000`) | Flushed memory goes as pieces the phone's upload store holds (patch 0047) |
| 16 (`0x10000`) | Buffer views use guest-assigned handles (requires bit 7; patch 0057) |
| 18 (`0x40000`) | Batched descriptor sets without inline uniform blocks; this driver never offers it |
| 19 (`0x80000`) | Descriptor sets, inline uniform blocks included, allocated and written in the guest and committed with the next submit (patches 0067, 0072) |
| 20 (`0x100000`) | Batched descriptor pools' set ids are the guest handles after the pool's, chosen in the guest (requires bit 7; patch 0085) |
| 21 (`0x200000`) | Completion watches name the queries and coherent memory a batch ends and writes, and the records bring their captures (requires bit 9; patch 0086) |
| 22 (`0x400000`) | The device stream takes `WAIT_SERIAL`, so waits may be speculated (requires bit 9; patch 0089) |
| 23 (`0x800000`) | Silent success: no replies for the commands the guest does not wait for, failures on the feed (requires bits 7 and 9; used with bits 8, 12 and 16 too; patch 0087) |

## Runtime switches

| Variable | Effect |
| --- | --- |
| `CABOOSE_GFXSTREAM_SOCKET` | Socket path of the broker; selects the Caboose transport |
| `CABOOSE_GFXSTREAM_SURFACE_SOCKET` | Socket path of the broker's surface service |
| `CABOOSE_GFXSTREAM_GUEST_HANDLES=0` | Do not offer guest-assigned handles |
| `CABOOSE_GPU_SPECULATE=0` | Never report a wait complete before its record arrives, with `WAIT_SERIAL` granted or not (patch 0089) |
| `CABOOSE_READ_PROFILE=1` | Every two seconds and at exit, the eight opcodes with the most blocking read time (`opN` waiting for its own reply, `drainN` for earlier deferred replies, `waitN` for local waits), on stderr; calls above opcode 21009 are named (`wait_WaitSemaphores`); `speculated=N` counts the waits reported complete before their records since the process started |
| `CABOOSE_COMMAND_PROFILE=1` | Every two seconds and at exit, the twelve commands that took the most device-stream bytes (`opN=KiB/count/mean bytes`), and the total bytes and commands, on stderr |
| `CABOOSE_PRIVATE_GPU_COHERENT_LOG=1` | The first coherent-memory flushes and invalidates, per allocation, on stderr |
| `CABOOSE_PRIVATE_GPU_FLUSH_TIMING=1` | Bounded flush timing records on stderr |
| `CABOOSE_PRIVATE_GPU_RPC_TIMING=1` | Bounded timing of ten synchronous calls on stderr |

## Tests

`python3 -m unittest discover -s guest/gpu/gfxstream -p 'test_*.py'` checks the series
(contiguous numbering, upstream-only changes, descriptions, pinned revision) along with
the broker, and that silent success's commands are the decoder's. `compile.sh` runs
`check_silent_success.py` on the prepared tree before every build: it fails when the encoder
defers the reply of a command silent success does not list, or reads the reply of one it
does. The owned headers' C++ tests are described in their READMEs.

[`sync-check/`](sync-check/README.md) runs the event, query, free and reply-wait paths
against a real phone executor and times them, for a driver build before it is installed.
